## 1. Назначение и статус

На 23.09.2026 реализовано расчётное ядро с JSON CLI и синтетическими примерами: [реализация и запуск](IMPLEMENTATION.md), [отчёт проверок](TEST_REPORT.md). Калькулятор подбирает конфигурации аккумуляторных батарей Yellow для ИБП по мощности нагрузки и требуемой автономии. Инженерный режим рассчитывает конфигурацию по ступенчатой нагрузке и время работы выбранной конфигурации.

Документ объединяет требования из писем 2016 года, предоставленные расчёты Mathcad и результаты аудита листовок. Обозначения:

- **И** — утверждённое требование из исходных материалов.
- **П** — предложенное ранее и утверждённое пользователем решение. **И/П** также утверждено; метки сохраняются для происхождения требований.
- **У** — нужен источник данных или решение перед выпуском соответствующей функции.

23.09.2026 пользователь утвердил решения И, И/П и П. Пометка У сохраняет необходимость получения данных или технической проверки; утверждение решения не означает выполнения проверки.

**Производственная база создаётся с нуля, первоначально только для серий HR-M и HR-WM. Источник наполнения — согласованные данные новых листовок, готовящихся в параллельной задаче. Состав первой версии: простой подбор, инженерный подбор по ступеням, обратный расчёт для постоянной нагрузки, общая база характеристик, проверка ограничений, сохранение состава расчёта. ## 3. Простая версия

### Ввод

| Поле | Правило | Статус |
|---|---|---|
| Мощность нагрузки | Положительное число; единица кВт или кВА | И |
| Коэффициент мощности | Для кВА: `0 < PF ≤ 1`; при кВт не участвует | И / П: валидация |
| КПД инвертора | Проценты; `0 < η_percent ≤ 100`; расчётная доля `η_percent / 100` | И / П: валидация |
| Количество АКБ в линейке | Положительное целое | И |
| Номинальное напряжение DC | Альтернативный ввод для определения длины линейки; не заменяет конечное напряжение | И |
| Конечное напряжение разряда | В/элемент; набор допустимых значений из таблиц моделей | И |
| Требуемая автономия | Минуты; обязательно поддержать 180 мин | И |
| Максимальное число параллельных линеек | Положительное целое, утверждено по умолчанию — 5 | И / П: значение |

П: длительность разрешить вводить числом, рядом дать быстрый выбор 5, 10, 15, 30, 60, 120, 180 минут. Наличие значения в форме не означает, что каждая модель поддерживает такой срок по своим данным.

П: переключатель способа задания линейки «Количество АКБ / Напряжение DC». Второе значение вычисляется и показывается только для чтения. Для шестиячеечных 12 В моделей `U_nominal = N_series × 12`. При нецелом результате деления показать ошибку совместимости, не округлять автоматически. Структура данных должна поддерживать иное число элементов/напряжение батареи; первая поставка ограничена подтверждёнными моделями.

Базовые условия простой версии: 25 °C, коэффициенты старения и запаса равны 1 (П). Показать эти условия рядом с результатом и дать переход в инженерный режим. Это оценка на исходных характеристиках, а не обещание срока службы.

### Подбор и выдача

1. Исключить серию с точным идентификатором `AB` (И). Не исключать `ABF` по префиксу.
2. Первая версия включает только HR-M и HR-WM из новой базы. Историческое требование о HRL 12-100 сохраняется для контекста, но не добавляет старую модель в текущий каталог. Артикулы и принадлежность к серии берутся из новых листовок без автоматического переименования.
3. Для каждой модели рассмотреть целые `N_parallel` от 1 до заданного максимума (П).
4. Рассчитать время по модели, выбранному конечному напряжению и мощности на элемент. Провести доступные проверки ограничений.
5. При запросе 10 минут включать близкие варианты 8–12 минут (И). Общий диапазон ±20% для остальных сроков утверждён (П); границы включены.
6. Разделять достигшие заданного времени конфигурации и варианты ниже цели. Например, 8,5 мин при цели 10 мин — «на 1,5 мин меньше», а не успешный подбор (П).
7. Убирать явно избыточную выдачу (И). Утверждено: ближайшие варианты в заданном диапазоне; расширение диапазона только по действию пользователя. Если подходящих нет — сообщать об этом, не скрывать изменение условий (П).
8. Внутри группы сортировать по абсолютному отклонению времени, затем по меньшему числу параллелей, затем по общему количеству АКБ и артикулу (П). Показывать первые 10 строк и кнопку остальных; не удалять варианты из набора результатов (П).

Столбцы: модель/ссылка, фактическая автономия, параллельные линейки, количество АКБ, проверка ограничений. В раскрываемой строке: число АКБ в линейке, мощность/элемент, расчётный ток, напряжение и источник данных. Округление времени не должно превращать результат ниже цели в результат, достигший цели: сравнивать по неокруглённому значению.

Наличие — будущий отдельный столбец (И). Не выводить «в наличии» без источника и времени обновления.

## 4. Инженерная версия

### 4.1 Подбор по профилю нагрузки

Ввод: точная модель АКБ, число батарей в линейке, конечное напряжение, температура, коэффициент старения, коэффициент запаса; таблица этапов «мощность / длительность». Пользователь добавляет, удаляет и переставляет этапы. Общая длительность и ступенчатый график обновляются вместе с таблицей (И — данные Mathcad; П — интерфейс).

П: единица мощности, PF и КПД общие для профиля в первой версии, как в предоставленном примере. Нулевая мощность внутри профиля допустима; отрицательная — нет. Длительность каждого этапа строго положительная. Не выполнять подбор для профиля, полностью состоящего из нулей. Длительности — длины этапов, а не накопленное время.

Выход: требуемая нескорректированная и скорректированная ёмкость, число параллелей с округлением вверх, установленная ёмкость, общее количество АКБ, определяющая секция, таблица секционных результатов, график нагрузки, результаты проверок, применённые коэффициенты и источники.

### 4.2 Время автономии заданной конфигурации

Ввод: модель, количество АКБ в линейке, число параллелей, постоянная нагрузка, PF при кВА, КПД, конечное напряжение и коэффициенты. Выход: время, границы применимости, мощность на элемент, доступная скорректированная ёмкость и статус ограничений (И).

Обратный расчёт произвольного ступенчатого профиля в первую версию не включён: в переданном втором Mathcad-файле используется постоянная нагрузка.

## 5. Расчётная спецификация

### 5.1 Единицы и базовые формулы

Внутренние единицы: Вт, В, А, А·ч, минуты, °C. `c` — число элементов в одной батарее, `Ns` — число батарей в линейке, `Np` — число параллельных линеек.

```
P_ac_W = load_kW × 1000                        при кВт
P_ac_W = load_kVA × 1000 × PF                  при кВА
eta = efficiency_percent / 100
P_dc_W = P_ac_W / eta
P_cell_W = P_dc_W / (Ns × c × Np)
N_total = Ns × Np
```

Собственное потребление ИБП отдельно не добавлять в первой версии: такого обязательного поля в ТЗ Yellow нет. Оно есть в GE-примере; при будущем добавлении определить, включает ли введённый КПД эти потери, чтобы не учесть их дважды.

Мощность `W/battery` делится на число элементов для получения `W/cell`. Напряжение `V/battery` также делится на число элементов. Ток через последовательную цепь не делится и не умножается на число элементов. Данные на элемент и на батарею хранятся с явными единицами.

### 5.2 Интерполяция и обратный расчёт

Исправление от 25.09.2026 по замечанию пользователя: естественный кубический сплайн мощности по времени `interp(lspline(t, P), t, P, x)`, как в обоих исходных Mathcad. Вторые производные на концах равны нулю. Прежняя трактовка `lspline` как кусочно-линейной интерполяции была ошибочной. В узлах возвращать исходные числа. Не округлять промежуточные значения.

Обратную задачу решать внутри подтверждённого диапазона, ограниченным поиском корня того же сплайна; переставлять оси и строить обратный сплайн нельзя. Только действительно постоянный сплайн даёт интервал. Равные соседние табличные значения не гарантируют плоского участка кубического сплайна. При возрастании сплайна между узлами расчёт для кривой блокируется с явным сообщением, без скрытого перехода на линейный метод. Некорректно возрастающую таблицу не инвертировать автоматически.

За пределами таблицы не экстраполировать. Если нагрузка ниже мощности последнего узла, показывать границу «не менее последнего времени таблицы» только при подтверждённой монотонности; точное время неизвестно. Это не позволяет обещать 180 минут по таблице, заканчивающейся на 60 мин. Если нагрузка выше мощности первого узла, показывать «меньше нижней границы таблицы», без выдуманного времени.

Нет строки выбранного напряжения — нет расчёта для этой модели/условия. Интерполяция между напряжениями в первую версию не входит (П).

### 5.3 Секционный расчёт по мощности

Ниже — формализация для переноса предоставленного Mathcad, а не независимая верификация стандарта. До выпуска сверить порядок индексов, суммы и коэффициенты с независимыми расчётами. При сверке с Mathcad использовать одинаковые синтетические данные или новые данные HR-M/HR-WM в обоих расчётах; старые встроенные таблицы не переносить (У).

Для одного условного ряда батарей:

```
p[i] = P_dc_W[i] / (Ns × c)
delta_p[1] = p[1]
delta_p[i] = p[i] - p[i-1]
T[i,j] = сумма длительностей этапов i…j
K(t) = C_nominal_Ah / discharge_power_W_per_cell(t)
C_section[j] = сумма по i=1…j: delta_p[i] × K(T[i,j])
C_base = max(C_section[j])
C_required = C_base × K_age × K_reserve × K_temperature
Np = ceil(C_required / C_nominal_Ah)
```

Сохранять отрицательные изменения мощности; не заменять их нулём. Выбирать максимум по секциям, а не последнюю секцию. Все используемые `T[i,j]` должны попадать в диапазон данных; неподдерживаемый профиль получает явную причину невозможности расчёта.

Номинальная ёмкость здесь — паспортный параметр конкретной модели с условиями C10/C20. Нельзя переносить `K(t)` между моделями только по одинаковой ёмкости.

П: коэффициенты старения и запаса ≥1. У2 — порядок температурной поправки утверждён: использовать только подтверждённые данные производителя для новых HR-M/HR-WM, включая условия и диапазон применимости; хранить их в едином наборе. Пока таких данных нет, расчёт доступен только при температуре исходной разрядной таблицы, где `K_temperature=1`. Для других температур показывать «нет данных», не подставлять универсальный коэффициент. Старую температурную таблицу не импортировать. Числовые данные и метод их интерполяции ещё предстоит получить и проверить; использование `cspline` в историческом Mathcad само по себе не определяет метод для новых данных (У).

Для обратной задачи постоянной мощности после проверки этой трактовки коэффициентов:

```
K_total = K_age × K_reserve × K_temperature
P_equivalent_cell = P_dc_W × K_total / (Ns × c × Np)
time = inverse_discharge_curve(P_equivalent_cell)
```

Коэффициенты применяются один раз. Этот подход должен совпасть с обратным Mathcad на одинаковых синтетических данных либо одной новой модели HR-M/HR-WM и одной версии её новых данных (У).

### 5.4 Токовые ограничения

У3 — порядок утверждён пользователем. Допустимые токи АКБ берутся из подтверждённых данных производителя с длительностью и условиями. Клеммы, перемычки и защита проверяются только по данным выбранного исполнения. При недостатке данных показываются автономия и расчётный ток со статусом «токовые ограничения не проверены». При превышении подтверждённого предела конфигурация исключается из рекомендуемых с указанием причины. Получение самих пределов остаётся технической зависимостью.

И: расчёт должен учитывать токовую применимость. П: оценивать ток каждой линейки при минимальном поддерживаемом рабочем напряжении и фактической мощности этапа:

`I_string = P_dc_W / (Np × Ns × c × U_end_cell)`

Это оценка при равномерном распределении тока между линейками и заданном КПД; она не учитывает сама по себе падение на кабелях и не является полной тепловой проверкой соединений. Указать это в инженерных подробностях. Для реального ограничения нужны подтверждённые условия токов АКБ, клемм, перемычек и защиты (У).

Не сравнивать длительный разряд с паспортным током «5 секунд» как с длительно допустимым. Не подменять подтверждение допустимого тока клемм таблицей разряда постоянным током. Отдельно хранить статус батареи и соединений.

Выводить три состояния: «проверено по указанным пределам», «предел превышен», «недостаточно данных для проверки». Последнее не равно успешной проверке. Расчёт автономии допускается показать отдельно со статусом «токовые ограничения не проверены»; не включать его в полностью проверенные рекомендации (П).

## 6. База данных и управление версиями

Утверждено: база создаётся с нуля для HR-M и HR-WM. Калькулятор и новые листовки используют одну согласованную версию данных. Старые 102 таблицы и их исправления не являются заготовкой этой базы. Пока пакет из параллельной задачи не передан, реальные модельные записи не заполнять. Хранить:

- стабильный ID модели, точный артикул Yellow, серию, статус включения в подбор;
- заводской артикул отдельно и статус подтверждения соответствия;
- напряжение, число элементов, номинальную ёмкость и условия её измерения;
- режим разряда, температуру, напряжение отсечки, времена и числовые значения;
- исходную и нормализованную единицы, исходные значения без подмены;
- путь/ссылку на документ, страницу, ревизию, SHA-256;
- корректировки отдельными записями «было / стало / основание / принявший / дата»;
- проверку данных, область допуска (режим/условия) и версию набора;
- токовые пределы с длительностью, температурой и областью применимости.

Состояния П: `extracted`, `needs_review`, `approved`, `retired`. Допуск должен быть возможен для конкретной таблицы/области условий, чтобы ошибка токовой строки не объявляла автоматически корректной или некорректной всю модель. Текущий статус `extracted_not_approved_for_production` не разрешает производственный расчёт.

Ошибки прежних листовок остаются в историческом аудите и не являются списком исправлений для новой базы. Текущая зависимость — получение согласованного пакета HR-M/HR-WM из параллельной задачи, включая точные артикулы, единицы, условия и версии. Неполные поля не заполнять из исключённых источников.

## 7. Архитектура и интеграция — утверждённые решения

Расчётное ядро не зависит от интерфейса: отдельные операции нормализации, интерполяции, инверсии, простого подбора, секционного подбора и проверки ограничений. Оба режима используют одни функции и один набор данных. Не обращаться к старому русскому калькулятору для вычислений новой версии.

Технологию интеграции выбрать после распаковки и проверки проекта нового сайта. Настоящее ТЗ не предписывает React или конкретный серверный фреймворк. Пакет английского сайта в архиве пока справочный; его устаревшие адреса и настройки не использовать автоматически.

В результат включать введённые параметры, нормализованные значения, режим, модель, версию алгоритма, версию данных и статусы проверок. При изменении ввода помечать прежний результат как устаревший. Ошибки одной модели в массовом подборе не должны уничтожать остальные результаты; показывать количество и причины исключений.

П: основная локаль английская для нового сайта, русская — для внутренней проверки. Принимать десятичную запятую или точку, запрещать неоднозначные строки с обоими разделителями. Перевод не изменяет исходные числа и ID моделей.

## 8. Интерфейс и приёмка

Структура экранов и состояния: [INTERFACE.md](INTERFACE.md). Проверочные сценарии: [ACCEPTANCE.md](ACCEPTANCE.md), машиночитаемые арифметические примеры: [reference-cases.json](reference-cases.json).

Приёмка требует: прохождения арифметики и границ; отсутствия скрытой экстраполяции; правильного исключения AB; корректного различения ABF и M/WM; отображения токовой неопределённости; совпадения инженерных расчётов с Mathcad на одной версии данных. Утверждённый допуск для воспроизведения численного результата Mathcad — 0,1%, времени — 0,1 мин при той же интерполяции (П). Само выполнение сверки остаётся открытым (У). Это допуск программной сверки, не точность реальной батареи.
